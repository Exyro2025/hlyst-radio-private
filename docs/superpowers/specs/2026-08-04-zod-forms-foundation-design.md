# Zod validation + shadcn form foundation

**Date:** 2026-08-04
**Status:** design — awaiting review
**Scope:** foundation plumbing + one vertical slice (Webhooks)

## Problem

The station has **93 user-input surfaces in `web/`** — 78 genuine write forms, 15
filter/search-only controls. Only 10 are real `<form>` elements; the rest are
controlled React state plus a save button. They post to roughly **75 write
endpoints across 29 controller route files**.

None of it is schema-validated. Today:

- **`web/` has no validation library at all.** No zod, no react-hook-form, no
  formik. Client-side checks are hand-written predicates.
- **`controller/` depends on zod `^4.4.3`, but only for LLM structured output** —
  22 files under `llm/internal/prompts/**`, `llm/internal/tools/**`,
  `broadcast/dj-agent/schemas.ts`, `music/tagger-core.ts`. `grep -rln zod
  controller/src/routes/` returns nothing. **No HTTP request body is validated
  by zod.**
- Server-side validation is hand-rolled in `controller/src/settings/validate.ts`
  — **713 lines**, 11 `validate*Strict` functions — plus
  `settings/compat-params.ts` and `settings/vocab.ts`.

### The cost, measured on one feature

Webhooks is the smallest complete feature in the app. Its rules are restated
across **four files in five separate declarations**:

| # | Location | What it restates |
|---|---|---|
| 1 | `controller/src/settings/vocab.ts:891` — `interface Webhook` | the shape |
| 2 | `controller/src/broadcast/webhooks.ts:28` — `interface WebhookConfig` | the shape, again |
| 3 | `web/components/admin/WebhooksPanel.tsx:17` — `interface Webhook` | the shape, a third time |
| 4 | `vocab.ts:1039` **and** `broadcast/webhooks.ts:19` — `WEBHOOK_EVENTS` | the legal event list, twice |
| 5 | `validate.ts:544` `validateWebhooksStrict` **and** `WebhooksPanel.tsx:46` `valid()` | the rules (`/^https?:\/\//`, 500-char cap, non-empty events) |

`vocab.ts:1037` concedes the duplication in a comment: *"Kept in sync with
broadcast/webhooks.ts WEBHOOK_EVENTS — duplicated here so settings.ts has no
runtime dependency on the broadcast module."*

The client predicate at `WebhooksPanel.tsx:46` is the sharpest example. It
re-implements two of the server's four URL rules and silently omits the rest, so
the form can call a payload valid that `settings.update()` will reject.

## Goals

1. One schema per validated shape, authored once, executed on both sides.
2. Controller rejects malformed bodies at the route boundary with a field-level
   error payload, before `settings.update()` is reached.
3. `web/` forms validate against that same schema and render errors inline.
4. Prove all of the above on one real feature, leaving a convention the
   remaining ~77 forms can be converted against incrementally.

## Non-goals

- Converting the other 77 forms. Each becomes its own follow-up PR.
- Touching the `POST /settings` mega-endpoint. It validates the entire settings
  object at once and needs its own design.
- Replacing the other 10 `validate*Strict` functions. Only
  `validateWebhooksStrict` is retired here.
- Any change to the broadcast path, Liquidsoap IPC, or the LLM zod usage.

## Decisions

### Library choice: react-hook-form, not formik

Formik is effectively unmaintained. react-hook-form is what shadcn's own form
documentation is built on, it is uncontrolled by default (fewer re-renders on
the large admin editors), and `@hookform/resolvers/zod` gives direct zod
integration. Requires a `@hookform/resolvers` version with **zod v4** support,
to match the controller's `^4.4.3`.

### No `ui/form.tsx`

shadcn's `Field` primitives are **already vendored** at
`web/components/ui/field.tsx` (248 lines) — `Field`, `FieldLabel`,
`FieldDescription`, `FieldError`, `FieldGroup`, `FieldSet`, with
`data-[invalid=true]` styling wired through `fieldVariants`.

`FieldError` (line 204) already accepts `errors?: Array<{ message?: string }>`
— exactly react-hook-form's error shape. These primitives are built for RHF
interop.

So we do **not** add `ui/form.tsx`. Adding it would stand a second form
abstraction next to one that already exists and is currently used by only 3 of
27+ input-bearing files. Instead we raise `Field` adoption. This also sidesteps
the known Tailwind-v4 hazard: the shadcn CLI emits v3 CSS-variable syntax that
breaks this project's v4 setup, so nothing new gets generated by CLI.

### Sharing: generated mirror, following the theme-tokens precedent

`web/Dockerfile` copies only `web/`, and its `npm ci` runs against
`web/package.json` alone. `docker/Dockerfile.controller` copies only
`controller/`. A workspace package would mean editing both Dockerfiles,
`.dockerignore`, all three `lint.yml` matrix jobs, and the worktree
`node_modules` symlink setup.

The project already solved this exact problem. `controller/scripts/gen-theme-tokens.ts`
generates `web/lib/theme-tokens.generated.ts`, and `.github/workflows/lint.yml`
runs the generator then `git diff --exit-code`s the output. The generator's own
header states the constraint:

> "The web package can't import controller/src at build time (separate package +
> build context), hence a checked-in mirror kept honest by CI."

We follow it exactly.

```
controller/src/schemas/webhook.ts        ← source of truth
        │  npm run gen:schemas
        ▼
web/lib/schemas.generated.ts             ← committed mirror
        │
   ┌────┴────────────┐
   ▼                 ▼
zodResolver      validateBody() middleware
(client UX)      (authoritative)
```

## Architecture

### 1. `controller/src/schemas/` — isomorphic schema modules

New directory. **Hard rule: modules here may import only from `zod` and from
each other.** No `settings.js`, no `config.js`, no node builtins. This is what
makes verbatim mirroring safe, and it is enforced by an ESLint
`no-restricted-imports` rule scoped to the directory — not left to convention.

`controller/src/schemas/webhook.ts`:

```ts
import { z } from 'zod';

export const WEBHOOK_EVENTS = [
  'track.play',
  'dj.say',
  'dj.link',
  'request.received',
] as const;

export const WEBHOOKS_LIMIT = 16;
const ID_RE = /^[a-z0-9_]{3,32}$/;

export const webhookSchema = z.object({
  id: z.string().regex(ID_RE).optional(),
  url: z.string()
    .trim()
    .max(500, 'URL must be 500 characters or fewer')
    .regex(/^https?:\/\//, 'URL must start with http:// or https://'),
  events: z.array(z.enum(WEBHOOK_EVENTS))
    .min(1, 'Pick at least one event')
    .transform((xs) => [...new Set(xs)]),
  enabled: z.boolean().default(true),
  // '' = no header. The literal 'set' is the redaction sentinel meaning
  // "keep whatever is stored". Resolving it needs the CURRENT list, which a
  // schema does not have — see mergeWebhookSecrets().
  authHeader: z.string().max(500).default(''),
});

export const webhooksSchema = z.array(webhookSchema).max(WEBHOOKS_LIMIT);

export const webhooksPatchSchema = z.object({
  webhooks: webhooksSchema.optional(),
  trackPlayListenerGated: z.boolean().optional(),
});

export type WebhookInput = z.input<typeof webhookSchema>;
export type Webhook = z.output<typeof webhookSchema> & { id: string };
export type WebhookEvent = (typeof WEBHOOK_EVENTS)[number];
```

This single module replaces duplications 1–4 in the table above. `vocab.ts`
and `broadcast/webhooks.ts` re-export from it rather than redeclaring.

### 2. Three rules that deliberately stay out of the schema

A schema is a pure function of one value. Three of the existing rules are not,
and forcing them in would make the module non-mirrorable. Each gets an explicit
named step in `controller/src/schemas/webhook-server.ts` — a **server-only**
module, not mirrored:

**a. The `authHeader: 'set'` sentinel.** `getRedacted()` sends `'set'` to the UI
instead of the real header; the UI echoes it back to mean "unchanged". Resolving
it requires the existing list. Handled by `mergeWebhookSecrets(parsed, existing)`
after parse. The web mirror must never contain this — a browser has no stored
secret to merge.

**b. ID minting.** `mintId('wh_')` is a side effect, not a validation. The schema
marks `id` optional; the server mints one when absent.

**c. Cross-item ID de-duplication.** Two entries may parse individually yet
collide. Handled in the same server step, which re-mints on collision — matching
`validate.ts:571` exactly.

Keeping these three out is the load-bearing part of the design. It is why the
schema file can be copied byte-for-byte to the browser.

### 3. `controller/scripts/gen-schemas.ts` + CI drift check

Modelled on `gen-theme-tokens.ts`. Concatenates every `controller/src/schemas/*.ts`
(excluding `*-server.ts`) into `web/lib/schemas.generated.ts` with a
do-not-edit header, rewriting relative imports away since the output is one file.

`controller/package.json`: `"gen:schemas": "tsx scripts/gen-schemas.ts"`.

`.github/workflows/lint.yml`, in the existing `controller` matrix leg, directly
after the theme-token step:

```yaml
- name: Verify schema mirror is up to date
  if: matrix.package == 'controller'
  run: |
    npm run gen:schemas
    git diff --exit-code ../web/lib/schemas.generated.ts
```

### 4. `controller/src/middleware/validate.ts`

```ts
export function validateBody(schema) {
  return (req, res, next) => {
    const r = schema.safeParse(req.body);
    if (!r.success) {
      return res.status(400).json({
        error: firstMessage(r.error),        // back-compatible flat string
        fieldErrors: flattenIssues(r.error), // new: { 'webhooks.0.url': '...' }
      });
    }
    req.body = r.data;
    next();
  };
}
```

**Error contract is additive.** Every existing client reads `{ error }` from a
400 and keeps working unchanged; `fieldErrors` is new and optional. `error` is
the first issue's message, so the string stays human-readable in the toast that
`WebhooksPanel` already shows.

### 5. `settings.update()` stays the chokepoint

The route middleware is **not** a replacement for `settings.update()`'s own
validation. `update()` is reached by paths that never touch
`routes/webhooks.ts` — backup import, onboarding save, direct settings patches —
and CLAUDE.md treats it as the single validation chokepoint for persisted state.

So `validateWebhooksStrict` is **not deleted**. Its 54 lines of hand-rolled
checks are replaced by a call into the shared schema plus the server-only merge:

```ts
export function validateWebhooksStrict(raw: unknown, existing: Webhook[] = []) {
  const parsed = webhooksSchema.parse(raw);          // shape + format
  return mergeWebhookSecrets(parsed, existing);      // sentinel, minting, dedupe
}
```

Same name, same signature, same throwing behaviour — so every existing caller is
untouched. This makes the change strictly additive at the persistence layer: the
middleware is an **early, field-level check that improves the error message the
form receives**, while `update()` remains authoritative. A body that somehow
bypasses the route is still validated by exactly the same schema.

### 6. Web form layer

`web/lib/form.ts` — one thin helper, `useZodForm(schema, defaults)`, wrapping
`useForm({ resolver: zodResolver(schema) })` so the resolver wiring is written
once rather than in each of the eventual 78 forms.

`WebhooksPanel.tsx` converts to `useFieldArray` over `webhooksSchema`, rendering
each row with the existing `Field` / `FieldLabel` / `FieldError` primitives. The
hand-rolled `valid()` (line 46) and the local `interface Webhook` (line 17) are
deleted; the type is imported from the generated mirror.

Server `fieldErrors` are mapped back onto the form via RHF's `setError`, so a
rule that only the server can check still lands on the right input.

## Testing

`controller/scripts/schemas.test.ts` (auto-discovered by `npm test` — dropping
the file in is the whole registration step):

Tests target the retained `validateWebhooksStrict` — the public contract that
must not move — not the schema in isolation:

1. Every input the old implementation accepted is still accepted, with an
   identical returned object.
2. Every input it rejected still throws. Ported case-by-case from the existing
   rules: non-array, over 16 entries, bad scheme, >500-char URL, empty events,
   unknown event name.
3. `authHeader: 'set'` with a prior value keeps it; without a prior value yields
   `''`; any other string replaces.
4. Duplicate ids across entries are re-minted.
5. Event de-duplication preserves first-seen order.
6. `webhooksPatchSchema` accepts each field independently — the route's existing
   "toggle saves without re-submitting the hook list" behaviour must survive.

Plus: `npm run gen:schemas && git diff --exit-code` locally before pushing, and
`npm run lint` in both `controller/` and `web/` (the merge gate).

Manual verification via the `verify` skill — isolated controller on a spare port
with a temp `STATE_DIR`, worktree Next dev server, Playwright against
`/admin/connect?tab=webhooks`: add a hook, submit a bad URL and confirm the
inline error, save a valid one, confirm the auth header survives a round-trip
without retyping, and confirm the listener-gate toggle still saves alone.

## Migration path

Once merged, converting a form is mechanical:

1. Add `controller/src/schemas/<feature>.ts`; move rules out of its
   `validate*Strict`.
2. Put anything stateful (sentinels, cross-item checks, minting) in
   `<feature>-server.ts`.
3. `npm run gen:schemas`.
4. Add `validateBody()` to the route.
5. Convert the panel to `useZodForm` + `Field`.

Suggested order, cheapest-first: **stations** (2 forms, own endpoint) →
**shows** (own endpoint, 216-line validator) → **skills** → **playlists** →
**imaging** → **onboarding** → the public request boxes. The `/settings`
mega-endpoint stays last and gets its own design.

## Risks

- **Mirror drift if CI is skipped.** Mitigated by the drift job living in the
  same matrix leg that already gates merges.
- **zod v4 + `@hookform/resolvers` compatibility.** Pin a resolver version with
  v4 support; verified by `web`'s `tsc --noEmit`, which is part of the gate.
- **Web bundle size.** zod is ~14 kB gzipped, and it lands only in admin chunks,
  which are already behind auth and not on the listener path. The 6 public
  request boxes are explicitly out of scope for this PR, so no listener-facing
  bundle grows.
- **Behaviour drift while porting `validateWebhooksStrict`.** Mitigated by test
  items 1–2, which port the old rules case-by-case rather than re-deriving them.
